# Драйвер Evolis Sig100 на Windows

`SignotecPadDriver` использует стандартный режим signoPAD-API/Web. `connect()`
подключается к WebSocket, ищет HID/USB-устройства и открывает планшет с индексом
`0`. После захвата драйвер закрывает планшет. Следующий захват открывает его
снова через тот же WebSocket. `disconnect()` освобождает планшет и соединение.

Подключение к WebSocket ограничено 8 секундами, захват — 3 минутами. Драйвер
возвращает Base64 PNG и размеры из заголовка IHDR. Если чтение SignData
завершилось ошибкой, в консоль попадает код ошибки, а PNG остаётся доступным.

## Сверка с руководством signotec

- В §8.4.1 тип обработчиков WebSocket в таблице указан как `String`. Пример
  передаёт функции `onOpen`, `onClose`, `onError` без кавычек. Драйвер следует
  примеру и передаёт функции обратного вызова.
- В §8.1 и §8.5 команды получают объекты, созданные через `Params`. Для поиска
  используется `new Params.searchForPads()` и `setPadSubset('HID')`. Для открытия
  и закрытия индекс передаётся в конструктор `new Params.openPad(0)` или
  `new Params.closePad(0)`. Поиск нужен драйверу для проверки, что индекс `0`
  доступен после подключения.
- По §8.5.7 и §8.5.14–16 нажатия на планшете вызывают `handleConfirmSignature`,
  `handleRetrySignature` и `handleCancelSignature`. Драйвер отвечает командами
  `confirmSignature()`, `retrySignature()` и `cancelSignature()`. Само нажатие
  «Повторить» сообщает о запросе на очистку. `stopSignature()` завершает захват
  с сохранением точек и пригоден для другого сценария.
- В §8.5.4 `confirmationText` открывает отдельный диалог OK/Cancel **перед**
  захватом. В пилоте текст запроса передаётся в `setCustomText(prompt)`, а
  подтверждение выполняется кнопкой после подписи. В `CaptureOptions` есть
  `prompt` и `signal`. Для верхнего поля `setFieldName` драйвер использует
  фиксированную надпись «Подпись клиента».
- §8.5.10 и §9.6–9.8 описывают PNG (`FileType.PNG`), поле `file` и фиксированную
  толщину карандаша в пикселях. Для экрана порядка 320×160 выбрано **3 px**.
  Размер экспортируемого изображения зависит от области, занятой подписью.
  Для `getSignatureData()` сохраняется значение `rsaScheme` по умолчанию `NONE`.
- По §9.1 занятость и отсутствие планшета (`-4`, `-5`, `-8`, `-22`)
  дают `pad_not_found`, ошибки сертификата (`-46`…`-48`) и ошибки WebSocket —
  `service_unavailable`. Отмена и таймаут определяются событиями и таймером
  драйвера. Остальные отрицательные коды дают `unknown` с `driverCode`.
  В обработчике `handleError` используется второй аргумент `errorCode`.

[Руководство signoPAD-API/Web 3.5.0, §8.1–8.5 и §9](https://backend.signotec.com/wp-content/uploads/2026/06/signopad-api-web-doku-de.pdf)

## Проверка на Windows

1. На локальном Windows-ПК установите signoPAD-API/Web из дистрибутива signotec
   с вариантом 2 (`DefaultAndLocalhost`), запустите WebSocket Pad Server и
   подключите Sig100 по USB. В Edge при необходимости включите поддержку
   loopback по §5.5. Используйте сертификаты, установленные комплектом signotec.
2. Откройте `STPadServer.html` из того же дистрибутива в браузере сотрудника.
   Проверьте, что пример использует `wss://local.signotecwebsocket.de:49494`,
   видит планшет и может получить тестовую подпись. При другой конфигурации
   установки используйте соответствующий ей адрес.
3. Создайте каталог `web/public/vendor/` и скопируйте туда JS-файл библиотеки,
   подключённый в `STPadServer.html`. Драйвер по умолчанию ищет `STPadServerLib.js`. Для
   исходного имени файла задайте `VITE_SIGNOTEC_LIB_URL` в `web/.env.local`,
   например `VITE_SIGNOTEC_LIB_URL=/vendor/имя_файла.js`. Для другого адреса
   службы можно задать `VITE_SIGNOTEC_WS_URL`, например
   `VITE_SIGNOTEC_WS_URL=wss://localhost:49494` при варианте 3.
4. Из корня проекта запустите `npm ci` и `npm run dev -w web`. Откройте
   `http://localhost:5173/?pad=signotec`. Для проверки через интерфейс приложения
   запустите также `npm run dev -w server` и используйте PDF из `samples/`. На
   странице документа параметр должен быть в URL `/doc/<id>?pad=signotec`.
   После подключения экранов загрузки и разметки отметьте блок и нажмите
   «Подписать на планшете».
5. Пока экраны загрузки и разметки в ветке являются заглушками, проверьте
   драйвер из консоли DevTools на странице Vite. Введите следующий код и
   подтвердите вымышленную подпись на устройстве.

   ```js
   const { SignotecPadDriver } = await import('/src/pad/signotec.ts');
   const pad = new SignotecPadDriver();
   try {
     await pad.connect();
     const signature = await pad.capture({ prompt: 'Подписываю тестовый документ № 1' });
     console.log(signature.imageWidth, signature.imageHeight, Boolean(signature.signDataBase64));
     const preview = document.createElement('img');
     preview.src = `data:image/png;base64,${signature.imagePngBase64}`;
     document.body.append(preview);
   } catch (error) {
     console.error(error);
   } finally {
     await pad.disconnect();
   }
   ```

6. Поставьте штрих и нажмите «Повторить». Экран должен очиститься, после чего
   новая подпись и «Подтвердить» должны дать PNG. В следующем запуске нажмите
   «Отмена» и проверьте `PadError` с кодом `cancelled`. Повторите с отключённым
   USB, чтобы проверить `pad_not_found`, затем с остановленной службой, чтобы
   проверить `service_unavailable`.

## Не проверено без реального планшета

- **Сделано 20.11.2026:** файл библиотеки (`STPadServerLib-3.5.0.js`, MIT) получен из
  установленного дистрибутива и лежит в `web/public/vendor/STPadServerLib.js`. Загрузка файла в
  песочнице подтвердила имена методов и параметров, которые использует драйвер. Библиотека
  в браузере создаёт один объект `window.STPadServerLib`, загрузчик это учитывает. События
  `handleError` в библиотеке нет, ошибки команд приходят отклонёнными промисами. Пример
  `STPadServer.html` с планшетом Ali на Windows подпись получил.
- Не проверено: работа драйвера с настоящим планшетом на странице из Railway (HTTPS и
  `wss://local.signotecwebsocket.de:49494` из целевого браузера).
- Обнаружение конкретного Sig100, порядок событий кнопок, отмена в процессе
  захвата и повторное открытие после завершения.
- Отображение кириллицы и длина текста на экране 320×160, читаемость PNG с
  толщиной 3 px, выдача SignData в стандартном режиме и фактические коды ошибок
  службы при сбоях оборудования.
