# Подпись на планшете в CRM банка: материалы для составления ТЗ

Входной документ для аналитика, который готовит техническое задание программисту CRM. Здесь собрано: что строим, что уже сделано и проверено на демонстрационном стенде, что должен реализовать программист, что нужно от ИТ банка, какие вопросы остаются открытыми. Подробности логики — в [README.md](../README.md), перенос на C# — в [CSHARP.md](CSHARP.md), справка по планшету и службе signotec — в [SIGNOTEC.md](SIGNOTEC.md) и [BRIEF.md](BRIEF.md).

Дата: 21.11.2026. Статус: демонстрационный стенд работает, боевая реализация не начата.

---

## 1. Цель и рамки

**Цель.** Сотрудник банка в карточке документа CRM нажимает «Подписать», клиент расписывается на планшете Evolis Sig100, подпись автоматически ставится во все нужные места документа, подписанный PDF сохраняется в CRM.

**Решения заказчика (Ali, 21.11.2026):**
- Сервис подписания встраивается в CRM и работает на серверах банка. Документы клиентов не покидают серверы банка.
- Наш сайт на Railway — только демонстрация идеи и тестовый стенд. В боевой работе он не участвует.
- Боевую часть пишет программист на C#. От нас нужны логика, эталоны и материалы для ТЗ.
- CRM открывается в браузере на **собственных компьютерах сотрудников** фронт-офиса. Удалённый рабочий стол (RDP, Citrix) не используется.

**Что не входит в этот этап:** юридически значимая криптографическая подпись (сертификат, хэш, защита от изменений), подпись на Mac, несколько подписантов в одном документе, автоматический выбор мест подписи (см. раздел 9, вопросы 1, 5).

## 3. Архитектура в банке

```
Рабочий ПК сотрудника (Windows)                      Серверы банка
┌────────────────────────────────────────┐          ┌───────────────────────────────┐
│ Браузер (Chrome / Edge)                │  HTTPS   │ CRM (сайт, C#)                │
│  ├ Страница документа CRM              │◄────────►│  ├ Документы и права          │
│  │   + JS-модуль подписи (разметка,    │          │  ├ API подписи (новое)        │
│  │     драйвер планшета)               │          │  ├ Ядро PDF (новое): геометрия │
│  │            │ WebSocket (wss, :49494)│          │  │   и вставка подписи        │
│  │            ▼                        │          │  └ Хранилище, журнал действий │
│  └ Служба signoPAD-API/Web (signotec)  │          └───────────────────────────────┘
│            │ USB (HID)                 │
│            ▼                           │
│ Планшет Evolis Sig100 (signotec Sigma) │
└────────────────────────────────────────┘
```

Принципиально:
- **Браузер сам с планшетом работать не умеет.** Нужна служба signotec на каждом ПК, где подписывают. Служба бесплатная. Она слушает порт 49494 и общается с планшетом по USB. Протокол обмена с планшетом зашифрован производителем, обойтись без службы нельзя.
- **Картинка подписи приходит из браузера на сервер CRM.** Вставка в PDF выполняется на сервере CRM (на C#), а не в браузере. Так документ не обрабатывается на ПК сотрудника и вставка идёт по единым правилам.
- **Всё остальное** (хранение, права, журнал) делает CRM своими средствами.

## 4. Сквозной поток

1. Сотрудник открывает документ в CRM и нажимает «Подписать».
2. CRM отдаёт браузеру PDF и сведения о страницах (размер, поворот).
3. Сотрудник отмечает на страницах прямоугольники — **блоки подписи** (рисует мышью). В будущем блоки может расставлять сама CRM по шаблону документа (вопрос 5).
4. Нажимает «Подписать на планшете». JS-модуль подключается к службе signotec, открывает планшет, показывает на нём короткий текст («Подписываю документ: …»).
5. Клиент расписывается и нажимает «OK» на планшете (есть «Повторить» и «Отмена»).
6. JS-модуль получает от службы картинку подписи (PNG) и биометрические данные подписи (SignData), отправляет их на сервер CRM вместе со списком блоков.
7. Сервер CRM готовит картинку (прозрачный фон, обрезка, цвет), вставляет её в каждый блок PDF с учётом размера и поворота страницы.
8. Сервер сохраняет подписанный PDF (оригинал не изменяется), картинку подписи и SignData, пишет запись в журнал.
9. Сотрудник видит результат, подписанный PDF доступен в карточке документа.

Все ошибки (нет службы, нет планшета, отмена, истёк срок ожидания, неверные блоки) обрабатываются с понятными русскими сообщениями. Список кодов — в README, раздел 5 и 6.

## 7. Требования (черновик для ТЗ)

### 7.1. Функциональные

| № | Требование |
|---|---|
| FR-1 | Подпись запускается из карточки документа CRM пользователем с нужным правом. |
| FR-2 | Поддерживаются PDF без пароля до 25 МБ (значение настраивается); защищённые паролем отклоняются с понятным сообщением. |
| FR-3 | Блоки подписи размечаются на любых страницах; не больше 50 на документ; минимальный размер блока 2% страницы по каждой стороне. |
| FR-4 | Блок хранится в долях видимой страницы (0..1, начало слева сверху) и не зависит от масштаба и поворота страницы. |
| FR-5 | Клиент расписывается один раз; подпись ставится во все блоки. |
| FR-6 | Подпись вставляется с сохранением пропорций, по центру блока, прямо относительно читающего, в том числе на повёрнутых страницах и страницах с обрезкой. |
| FR-7 | Картинка подписи синего цвета (цвет шариковой ручки), с прозрачным фоном и без пустых полей. |
| FR-8 | Оригинал документа не изменяется; подписанный PDF хранится как отдельная версия. Повторная подпись создаёт новую версию из оригинала. |
| FR-9 | На экране планшета выводится короткий текст-подтверждение (до 60 символов); на планшете есть «OK», «Повторить», «Отмена». |
| FR-10 | Время ожидания подписи ограничено 3 минутами; отмена на планшете и в CRM прекращает подпись без ошибки. |
| FR-11 | Сообщения об ошибках понятны пользователю и содержат технические подробности для поддержки (код и причина от службы). |
| FR-12 | Для каждой подписи пишется запись журнала: пользователь, время, документ, число блоков, устройство, результат. |
| FR-13 | Биометрические данные подписи (SignData) сохраняются вместе с подписанным документом (вопрос 3). |

### 7.2. Нефункциональные и безопасность

| № | Требование |
|---|---|
| NFR-1 | Документы и подписи обрабатываются и хранятся только на серверах банка. |
| NFR-2 | Доступ только для авторизованных пользователей CRM, права проверяются на сервере для каждого действия. |
| NFR-3 | Идентификаторы документов в адресах не должны угадываться; доступ к документу проверяется правом пользователя на него. |
| NFR-4 | Подпись и SignData — персональные данные: срок хранения и доступ определяет ИБ банка (вопрос 3). |
| NFR-5 | Браузеры: актуальные Chrome и Edge на Windows 10/11 (служба поддерживает также Firefox и Opera). |
| NFR-6 | Работа без интернета: все обращения идут внутри сети банка и на локальную службу, внешние сервисы не используются. |
| NFR-7 | Служба signotec — только актуальной версии (в старых известна уязвимость отказа в обслуживании CVE-2020-9345). |
| NFR-8 | Целостность: рекомендуется сохранять SHA-256 оригинала и подписанного PDF (в демонстрации этого нет). |

### 7.3. Критерии приёмки

Основной чек-лист — [CSHARP.md, раздел 8](CSHARP.md). Кратко: на каждом из пяти тестовых PDF подпись попадает во все блоки, пропорции сохранены, подпись синяя, повёрнутая страница читается прямо; корректно отрабатывают отмена, отключённый USB, занятый планшет, истёкшее время; результат визуально совпадает с эталоном демонстрационного стенда.

## 8. Требования к рабочим ПК и сети (для ИТ банка)

Источник: документация signotec signoPAD-API/Web 3.5.0 ([PDF](https://backend.signotec.com/wp-content/uploads/2026/06/signopad-api-web-doku-de.pdf)). Проверено на одном ПК с Windows: установка, пример `STPadServer.html` и подпись на планшете работают.

- Windows 7 и новее, планшет по USB (режим HID, драйвер обычно не нужен).
- **Установка службы:** есть тихая установка без диалогов (параметры `CERT_SEL`, `ALLOW_EDGE_LOOPBACK` и другие, раздел 5.8 документации), поэтому раздача через GPO, SCCM или скрипт возможна. Пример команды: `signotec_signoPAD-API_Web_X.X.X.exe /s /v"/qn CERT_SEL=\"DefaultAndLocalhost\" ALLOW_EDGE_LOOPBACK=\"Yes\""`. Команда взята из документации, у нас не запускалась.
- **Адрес службы:** `wss://local.signotecwebsocket.de:49494`. Установка вариантов 1 и 2 добавляет запись `127.0.0.1 local.signotecwebsocket.de` в файл `hosts` (проверить, не мешает ли политика безопасности банка).
- **Сертификат:** собственный, подписан корневым «signotec GmbH CA», который ставится вместе со службой. Его нужно доверять в браузере. Проверить, не блокируется ли политиками.
- **Edge** по умолчанию блокирует обращения к `localhost`: нужен параметр установки `ALLOW_EDGE_LOOPBACK="Yes"`.
- **Прокси** должен пропускать локальный адрес мимо себя.
- Минимум TLS 1.1. Файл `PadConfig.ini` может переопределять порты и адреса.
- **Новые версии Chrome** могут показывать запрос на доступ к устройствам в локальной сети. Не проверено, проверить на стенде банка.
- Удалённый рабочий стол (RDP) службой **не поддерживается**; по сведениям заказчика, он не используется. Citrix требует отдельной настройки (не нужна).
- Антивирус и DLP банка могут влиять на службу и порт 49494: проверить на пилотных ПК.

## 9. Открытые вопросы для ТЗ

1. **Юридическая сила.** Какой тип подписи нужен банку (простая, усиленная) и по какому закону? Сейчас подпись вставляется как картинка и **юридической силы не имеет**. Для усиленной подписи потребуется отдельный модуль (хэш, сертификат, защита от изменений); signotec предлагает для этого продукт signoAPI, условия не выяснены.
2. **Тип документов.** Какие документы подписываются, нужно ли подписывать пачку документов за один раз.
3. **SignData.** Хранить ли биометрические данные подписи (нужны для экспертизы), сколько и где; кто имеет к ним доступ.
4. **Подписанты.** Один клиент на документ или несколько (клиент и сотрудник)?
5. **Места подписи.** Расставляет сотрудник или CRM автоматически по шаблону документа? Если автоматически, в каком виде CRM знает место (метка в тексте, координаты шаблона)?
6. **Права.** Какие роли могут подписывать, смотреть подписанные документы, отзывать подпись?
7. **Хранение документов в CRM.** Формат и место хранения, версионность, как подписанный PDF связывается с карточкой.
8. **Журнал и аудит.** Требования ИБ к содержанию и сроку хранения записей.
9. **Интерфейс.** Язык (русский, узбекский), стиль, как кнопка вписывается в существующие экраны CRM.
10. **Текст на планшете.** Экран 320×160 вмещает несколько слов. Нужен ли иной текст, нужен ли язык клиента.
11. **Парк оборудования.** Сколько рабочих мест и планшетов; кто устанавливает и обслуживает.
12. **JS-часть.** Готовый модуль одним файлом собран (см. раздел 6). Нужно решить: подключаем его как есть или программист CRM переписывает разметку на собственном компоненте CRM; допустимы ли внутренний скрипт и воркер из `blob:` по политике безопасности страницы (CSP).
13. **Сети и ИБ.** Допустимы ли запись в `hosts`, сертификат signotec CA, порт 49494, локальный WebSocket по политикам банка; нужно ли ограничение источников (origin) для службы — в документации signotec это не описано, вопрос остаётся к производителю.
14. **Mac.** Поддержки службы на macOS у signotec в открытых материалах не найдено; нужны ли Mac-рабочие места.

## 10. Риски и допущения

| Риск | Что с этим делать |
|---|---|
| Планшет и служба проверены, но **полный проход «планшет → страница → PDF» на реальном потоке не завершён**: при первой попытке нашлась ошибка в выборе индекса планшета (исправлено), после правок повторная проверка на Windows ещё не подтверждена | Повторить проверку на демонстрационном стенде; включить в пилот |
| Экран планшета 320×160: читаемость текста и кнопок не проверена | Проверить на планшете, при необходимости изменить текст |
| Толщина линии подписи (сейчас 3 px) может быть слишком тонкой | Подобрать на пилоте |
| Политики безопасности банка (hosts, сертификаты, локальный порт, антивирус) могут блокировать службу | Проверить на стенде ИТ до начала разработки |
| Юридическая сила не определена | Решение юристов банка, возможна замена подхода |
| Эталон на C# не запускался | Программист проверяет по контрольным числам и визуальному сравнению на тестовых PDF |
| Просмотр подписанного PDF во встроенном окне не проверен в обычном Chrome | Проверить; в CRM может быть собственный просмотрщик |

Допущения: CRM работает в браузере на Windows; ПК собственные; сервер CRM на C# (версия .NET и тип приложения не уточнены); планшет Evolis Sig100 (signotec Sigma).

## 11. Этапы работ

0. **ТЗ.** Согласование требований и ответы на вопросы раздела 9.
1. **Стенд банка.** Установить службу на 1–2 ПК, проверить планшет с нашей демонстрацией и с тестовой страницей CRM; проверить политики безопасности.
2. **Серверная часть.** Ядро PDF, API, хранение, журнал (программист CRM, по CSHARP.md).
3. **Интерфейс.** Разметка блоков и драйвер планшета в CRM.
4. **Пилот.** 3–5 рабочих мест, реальные сценарии, исправления.
5. **Развёртывание.** Массовая установка службы, обучение, поддержка.
6. **Приёмка** по чек-листу.

Оценки сроков не даю: они зависят от устройства CRM, которого мы не видели.
