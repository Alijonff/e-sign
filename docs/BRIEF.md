# Интеграция планшета Evolis Sig100 с документооборотом (браузер, Windows)

Бриф для старта проекта в Claude Code. Дата сбора: 2026-11-20. Всё ниже собрано из открытой документации signotec и Evolis. Что не проверено, помечено «НЕ ПРОВЕРЕНО».

## 1. Задача и требования

- Устройство: Evolis Sig100 (артикул ST-BE105-2-UEVL), USB, монохромный LCD 4", 320×160, резистивный сенсор, ручка без батарейки.
- Evolis Sig100 = signotec **Sigma** (ребрендинг). Ищите документацию и SDK под названиями **signotec Sigma / signoPAD-API**.
- Компьютеры сотрудников: Windows. Документооборот работает в браузере.
- Сценарий: сотрудник нажимает «Поставить подпись» → система сама определяет место подписи (логика в нашем документообороте) → на планшете клиент только ставит подпись → подписанный документ сохраняется.
- Нужна юридически значимая подпись. Биометрия (скорость, нажим) не критична.
- Уже проверено: **signoSign/2** (десктопная программа signotec) с этим планшетом работает.
- Страна и требования местного закона к подписи: **НЕ УТОЧНЕНО**, нужен юрист.

## 2. Компоненты signotec и как они связаны

| Компонент | Что делает | Где работает |
|---|---|---|
| **signoPAD-API/Web** | Служба на ПК + JavaScript-библиотека. Связывает браузер и планшет через WebSocket, плагины браузера не нужны. Бесплатна. | Рабочий ПК сотрудника |
| **signoPAD-API** (Windows/Java/Linux) | Нативный API управления планшетом: экран, подпись, данные. | Рабочий ПК |
| **signoAPI** | Захват, встраивание и проверка подписи в PDF (ISO 32000-1, Adobe DigSig). Платформы: Windows, Java (сервер, Windows/Linux), iOS, Android. Заявлено соответствие eIDAS для усиленной подписи. | Сервер или десктоп |
| **signoSign/2** | Десктопная программа подписания PDF. | Рабочий ПК |
| **signoSign/Universal** | Веб-приложение для подписания PDF с REST API и интеграцией через iFrame. SaaS или on-premises. Для планшета в браузере тоже использует signoPAD-API/Web. | Сервер или облако |

## 3. Выбранный подход (предварительно)

**Вариант А: наш документооборот управляет всем сам.**
1. Браузерный фронтенд через JavaScript-библиотеку signoPAD-API/Web запускает подпись на планшете.
2. Бэкенд получает подпись (изображение и/или SignData).
3. Подпись вставляется в PDF в место, которое определила наша логика.
4. Юридическая значимость обеспечивается отдельным модулем подписи и сертификатом. Кандидат: **signoAPI (Java-вариант на сервере)**. НЕ ПРОВЕРЕНО, подходит ли он под наш сценарий. Это главный вопрос к signotec.

**Вариант Б (запасной): signoSign/Universal.**
- В REST API есть операции вставки полей подписи с динамическим и статическим положением. Параметры координат в открытой документации не описаны (возможно, в Swagger UI).
- Автоматический запуск подписи на планшете по нажатию кнопки в документации не описан. НЕ ПРОВЕРЕНО.

Рекомендация на старт: пилот на варианте А с вставкой подписи как картинки для проверки удобства, параллельно выяснить у signotec юридическую часть.

## 4. signoPAD-API/Web: что нужно знать разработчику

Документация: PDF «signotec signoPAD-API/Web», версия 3.5.0 от 25.09.2025. Ссылки в разделе 8. Содержит главы по методам и ошибкам (глава 9.1 с кодами ошибок в сводке не просмотрена).

### Подключение
- Библиотека оборачивает WebSocket. Пространства имён: `STPadServerLibCommons`, `STPadServerLibDefault` (стандартный режим), `STPadServerLibApi` (API-режим).
- Первым вызовом идёт `createConnection(url, onopen, onclose, onerror)`. Promise нет. В конце `destroyConnection()`.
- Адреса по варианту установки:
  - варианты 1 и 2: `wss://local.signotecwebsocket.de:49494`
  - вариант 3: `wss://localhost:49494`
  - вариант 4 (без TLS): `ws://127.0.0.1:49494`
- Порт по умолчанию 49494.
- Имя JS-файла и ссылка на CDN в документации не названы. Брать из дистрибутива или у поддержки signotec.

### Порядок вызовов (стандартный режим)
1. `createConnection(...)`
2. `searchForPads({type: "HID"})`, необязательно
3. `openPad({padIndex})`, возвращает параметры экрана
4. `startSignature(params)`; параметры: `fieldName`, `customText`, `confirmationText`, `textLayout`, `dialogImage`
5. Необязательно: `handleNextSignaturePoint` для отрисовки в реальном времени
6. Кнопки на планшете: `confirmSignature()`, `stopSignature()`, `retrySignature()`, `cancelSignature()`
7. Получение результата: `getSignatureData({rsaScheme})`, `getSignatureImage({fileType, penWidth})`, `getSigningCert()`
8. `closePad({padIndex})`, затем `destroyConnection()`

```js
try {
  const params = new STPadServerLibDefault.Params.startSignature();
  params.setFieldName("Customer Signature");
  await STPadServerLibDefault.startSignature(params);
} catch (error) {
  console.error(error.errorMessage);
}
```

### Показ документа и текста на планшете
- Отдельного вызова «показать документ» в стандартном режиме нет. Варианты: `dialogImage` (Base64-картинка, только Windows) и `textLayout` для текстовых блоков.
- В API-режиме есть `Display.setImage`, `Display.setText`, `Display.setPDF` (с версии 3.3.0.0).
- Для экрана 320×160 текст договора целиком не поместится. Планшет, скорее всего, будет показывать краткое подтверждение («Подписываю документ №… от …»), а не сам документ. Проверить на макете.

### Данные подписи
- `getSignatureData` возвращает `signData` (Base64). В режиме RSA-подписи в планшете ещё `certId` и `rsaSignature`.
- `getSignatureImage` возвращает Base64-картинку.
- `getSigningCert` возвращает сертификат устройства (X.509).
- Шифрование биометрии: `enablePadEncryption(docHash, encryptionCert, ...)`, только Windows. SignData предназначен для хранения; точки «вживую» как биометрию использовать нельзя.

### Ошибки и события
- Ошибки приходят как reject с отрицательным `errorCode` и `errorMessage`. Каждый `await` оборачивать в try/catch.
- `batch([...])` (с версии 3.4.0) отправляет несколько команд одной пачкой.
- События: `handleDisconnect`, `handleNextSignaturePoint`, `handleLogging`, `handleError`, `handleConfirmSignature`, `handleRetrySignature`, `handleCancelSignature`.
- В примерах документации есть опечатки (`handleConfirmSelection`, `returnCode`). Не копировать слепо.

## 5. Развёртывание на рабочих ПК (чек-лист)

- Windows 7 и новее. Браузеры: Chrome, Firefox, Opera, Edge.
- **RDP-сессии не поддерживаются.** Для Citrix нужна настройка виртуального loopback-адреса. Проверить, как сотрудники подключаются к рабочим местам.
- Установщик: 4 варианта по сертификату и адресу (`CERT_SEL`: Default, DefaultAndLocalhost, Localhost, NoTLS). Поддерживается тихая установка (`/s /v"/qn ..."`), значит раскатка через GPO/MDM возможна.
- Варианты 1 и 2 прописывают запись в файл hosts.
- Используется собственный сертификат, подписанный корневым «signotec GmbH CA». Его нужно доверять в браузере.
- Edge по умолчанию блокирует localhost: параметр установки `ALLOW_EDGE_LOOPBACK="Yes"`.
- Вариант 4 (`ws://`) блокируется Firefox на HTTPS-страницах без смены настройки.
- Прокси должен пропускать локальный адрес мимо себя.
- Файл `PadConfig.ini` может переопределять порты и IP для поиска планшетов.
- Минимум TLS 1.1.
- Linux: возможен, но со своими требованиями (libusb, правило udev, ручная генерация сертификатов). Не наш случай.
- Происхождение запросов (origin/CORS) в документации не описано. Вопрос безопасности: любая страница в браузере сможет обратиться к локальной службе, если не ограничено. Уточнить у signotec.
- Известна уязвимость старых версий службы (CVE-2020-9345, отказ в обслуживании). Ставить актуальную версию.

## 6. Что вставлять в PDF и как определять место

- Место подписи определяет логика нашего документооборота. Передавать модулю подписи нужно: страницу, координаты и размер поля, либо привязку к метке в тексте.
- Для вставки подписи как картинки в PDF на сервере подойдут обычные PDF-библиотеки. Для юридически значимой подписи (хэш документа, сертификат, защита от изменений после подписания) нужен модуль подписи вроде signoAPI. НЕ ПРОВЕРЕНО.

## 7. Открытые вопросы (выяснить до начала разработки)

1. **Юридическая:** в какой стране и по какому закону подпись на планшете должна быть значимой? Какой тип подписи это требует?
2. **signotec:** подходит ли signoAPI для сценария «одна кнопка в нашей системе, подпись на планшете, подписанный PDF обратно на сервер»? Условия и цена лицензии? Есть ли тестовая лицензия?
3. **signotec:** можно ли в варианте Б (signoSign/Universal) запускать подпись на планшете автоматически по кнопке из нашей системы и задавать поля подписи координатами?
4. **Наш документооборот:** название и версия, формат хранения документов, есть ли внешние сервисы/iFrame/REST-хуки, как подключать собственный JS-модуль.
5. **Инфраструктура:** как сотрудники подключаются к ПК (локально или RDP/Citrix), политика установки служб и сертификатов, прокси.
6. **Экран:** хватает ли 320×160 для текста подтверждения? Какие языки и шрифты нужны?
7. **Количество рабочих мест** и сколько планшетов нужно.
8. **Хранение биометрии:** нужно ли хранить SignData (для экспертизы) или хватит изображения.

## 8. Предлагаемые первые шаги проекта

1. Установить signoPAD-API/Web на один тестовый ПК с планшетом, открыть пример `STPadServer.html` из дистрибутива, проверить `searchForPads` / `openPad` / `startSignature`.
2. Сделать минимальную страницу: кнопка → подпись → предпросмотр изображения из `getSignatureImage`.
3. Добавить серверную часть: принять подпись, вставить в тестовый PDF по координатам.
4. Параллельно отправить вопросы 1–3 в signotec/Evolis и юристу.
5. Подключить к документообороту.
