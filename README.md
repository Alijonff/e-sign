# e-sign — подпись PDF на планшете Evolis Sig100

Веб-приложение для офиса. Сотрудник загружает PDF, отмечает на страницах места для подписи, клиент один раз расписывается на планшете Evolis Sig100 (это signotec Sigma), и подпись автоматически ставится во все отмеченные места. Подписанный PDF сохраняется и скачивается.

Состояние на 21.11.2026: **демонстрационный пилот**. Подпись вставляется в PDF как картинка (синяя, как шариковая ручка). Юридически значимой электронной подписью (хэш документа, сертификат, защита от правок) это пока не является.

**Для аналитика, который готовит ТЗ:** этот сайт — демонстрация идеи. Боевая версия будет частью CRM банка на серверах банка, её напишет программист на C#. Начните с [docs/CRM-INTEGRATION.md](docs/CRM-INTEGRATION.md): рамки, роли, архитектура, требования, вопросы к заказчику. Порядок чтения: `CRM-INTEGRATION` → этот README (логика) → [docs/CSHARP.md](docs/CSHARP.md) (геометрия, код на C#, чек-лист) → [docs/SIGNOTEC.md](docs/SIGNOTEC.md) и [docs/BRIEF.md](docs/BRIEF.md) (планшет и служба).

## 1. Как работает программа (коротко)

1. Сотрудник открывает сайт и входит общим паролем.
2. Загружает PDF. Сервер проверяет файл, сохраняет оригинал и сообщает размеры страниц.
3. Сотрудник мышью рисует на страницах прямоугольники — **блоки подписи**. Блок хранится в долях видимой страницы (0..1), поэтому не зависит от масштаба и поворота.
4. Нажимает «Далее: подпись» и «Подписать на планшете».
5. Браузер через службу signotec на этом же компьютере показывает на планшете короткий текст («Подписываю документ: …») и ждёт подпись. Клиент расписывается и нажимает «OK» на планшете.
6. Браузер получает картинку подписи (PNG) и отправляет её на сервер вместе со списком блоков.
7. Сервер делает фон картинки прозрачным, обрезает поля, красит штрихи в синий цвет и рисует эту картинку в каждом блоке (с учётом размера и поворота страницы).
8. Сотрудник видит результат и скачивает подписанный PDF. Файлы на сервере удаляются через 7 дней.

Работает и без настоящего планшета: режим `mock` рисует подпись мышью в окне. Нужен для разработки на Mac и для проверок.

```

│ Браузер (Chrome/Edge)                   │  HTTPS    │ Node.js-сервер (Fastify)    │

│  │            разметка → подпись →      │  /api/*   │  ├ хранение документов      │
│  │            результат                 │           │  ├ ядро: вставка подписи    │
│  └ Драйвер планшета (signotec)          │           │  │       (pdf-lib, pngjs)   │
│        │ WebSocket wss://…:49494        │           │  └ раздача собранного сайта │
│        ▼                                │           │ Volume /data (документы)    │
│ Служба signoPAD-API/Web (signotec)      │           └─────────────────────────────┘
│        │ USB (HID)                      │
│        ▼                                │
│ Планшет Evolis Sig100 (signotec Sigma)  │
└─────────────────────────────────────────┘
```

- **Сайт и сервер — одно приложение.** Сервер отдаёт собранный интерфейс (`web/dist`) и API под `/api`.
- **Служба signotec ставится на компьютер сотрудника.** Браузер сам с планшетом работать не умеет: нужна служба `signoPAD-API/Web` (бесплатная). Она слушает порт 49494 и общается с планшетом по USB. Страница с Railway подключается к ней по `wss://local.signotecwebsocket.de:49494`.
- **Планшет скрыт за интерфейсом `PadDriver`.** Сейчас два драйвера: `mock` и `signotec`. Для C#-версии добавляется третий (см. [docs/CSHARP.md](docs/CSHARP.md)).
- **Контракт между сайтом и сервером** лежит в одном файле [shared/src/index.ts](shared/src/index.ts): типы запросов, ответов, ошибок и интерфейс планшета.

## 3. Логика по шагам

### 3.1. Вход

- Один общий пароль (`APP_PASSWORD`). Учётных записей нет.
- `POST /api/login` с `{password}`: пароль сравнивается через SHA-256 и `timingSafeEqual`. Успех — ответ 204 и cookie `sid` (HttpOnly, SameSite=Lax, Secure в production), срок 12 часов.
- Значение cookie: `<время окончания в мс>.<HMAC-SHA256 от времени, ключ SESSION_SECRET>`. Сервер проверяет подпись и срок, состояния сессий не хранит.
- Лимит попыток входа: 10 в минуту с одного адреса (ответ 429).
- Все адреса `/api/*`, кроме `login`, `logout` и `session`, без валидной cookie отвечают 401. Страница при 401 переходит на `/login`.

### 3.2. Загрузка документа

- `POST /api/documents`, multipart, поле `file`, лимит `MAX_UPLOAD_MB` (25 МБ по умолчанию).
- Проверки: файл начинается с `%PDF-` (иначе 422 `not_pdf`); PDF читается библиотекой (иначе 422 `pdf_invalid`); PDF не защищён паролем (иначе 422 `pdf_encrypted`).
- Для каждой страницы сервер определяет **видимый размер в пунктах** (учитывая CropBox, иначе MediaBox) и **поворот `/Rotate`**: 0, 90, 180 или 270. Для повёрнутой страницы ширина и высота меняются местами.
- Документу выдаётся случайный идентификатор (UUID v4). Файл сохраняется как `DATA_DIR/<id>/original.pdf`, рядом `meta.json` (имя, размер, страницы, время создания). Имя файла очищается от путей и управляющих символов и используется только для показа.

### 3.3. Разметка блоков

- Страницы показываются подряд вертикальной лентой. Отрисовка через `pdf.js`, лениво (только видимые страницы).
- Блок рисуется протягиванием указателя (мышь или палец). Минимальный размер: 2% страницы по каждой стороне, не больше 50 блоков, блок не выходит за страницу.
- Выбранный блок можно переносить, менять размер за 4 угловых маркера, удалять кнопкой или клавишей Delete/Backspace. Справа список «Стр. N · блок M», клик прокручивает к блоку.
- **Блок — это `{id, page, x, y, width, height}`.** `page` с нуля; `x, y, width, height` — доли **видимой** страницы (0..1), начало слева сверху, ось y вниз. Пересчёт в точки PDF делает только сервер.
- Состояние блоков хранится на странице документа в памяти. Перезагрузка страницы сбрасывает разметку.

### 3.4. Подпись на планшете

Порядок вызовов драйвера `signotec` (стандартный режим signoPAD-API/Web 3.5.0):

1. `createConnection(wss://local.signotecwebsocket.de:49494)`: ждём открытия до 8 секунд.
2. `searchForPads('HID')`: берём **первый найденный планшет** (индекс у службы может начинаться не с нуля и приходить строкой).
3. `openPad(индекс)`.
4. `startSignature`: поле «Подпись клиента», на экране планшета текст «Подписываю документ: <имя без .pdf>» (до 60 символов).
5. Клиент расписывается. Кнопки на планшете: «OK» (событие `handleConfirmSignature`), «Повторить» (очистка, подпись продолжается), «Отмена» (`handleCancelSignature`).
6. После «OK»: `confirmSignature()`, затем `getSignatureImage` (PNG, толщина пера 3 px) и `getSignatureData` (биометрические данные для хранения; если не получились, подпись всё равно принимается).
7. `closePad`, при выходе с экрана `destroyConnection`.

Ограничения и защиты: подпись ждём не дольше 3 минут (код `timeout`); отмена и уход с экрана подписи отменяют подпись на планшете (при закрытии вкладки браузер просто разрывает соединение со службой; как служба при этом освобождает планшет, не проверено); одновременно только одна подпись; отключение USB во время подписи даёт ошибку `pad_not_found`.

Ошибки показываются по-русски с кнопкой «Повторить», внизу строка «Подробности» с технической причиной и кодом службы.

### 3.5. Вставка подписи на сервере

`POST /api/documents/:id/sign` с `{blocks, signature: {imagePngBase64, signDataBase64?, padKind}}` (тело до 5 МБ):

1. Проверка блоков (страница существует, числа корректны, не меньше 2%, внутри страницы, id уникальны, не больше 50).
2. **Подготовка картинки подписи** (`normalizeSignaturePng`): светлые пиксели (яркость от 235) становятся прозрачными, штрихи получают прозрачность по тёмности, весь штрих красится в синий (RGB 20, 40, 170), пустые поля обрезаются (оставляется 4 px). Пустая картинка — ошибка `invalid_signature`.
3. **Вставка** (`stampSignature`): оригинал читается заново при каждой подписи, картинка вписывается в каждый блок с сохранением пропорций, по центру, с отступом 4% от меньшей стороны блока. Поворот страницы учитывается так, чтобы подпись всегда стояла прямо относительно читающего.
4. Сохранение `signed.pdf`, `signature.png`, `signdata.b64`, обновление `meta.json` (время подписи). Запись атомарная с откатом при ошибке. Повторная подпись разрешена: берётся оригинал, `signed.pdf` перезаписывается.
5. Ответ: информация о документе и число заполненных блоков.

### 3.6. Результат и скачивание

- Экран показывает «Документ подписан», встроенный просмотр подписанного PDF и две кнопки: «Скачать» и «Загрузить другой документ».
- `GET /api/documents/:id/signed` отдаёт PDF с именем `<имя>-подписано.pdf` и заголовком `Cache-Control: no-store`.

### 3.7. Хранение и очистка

- Каталог документа: `DATA_DIR/<uuid>/` с правами 0700. Идентификатор из адреса проверяется регулярным выражением UUID v4 до обращения к диску.
- Очистка при старте сервера и раз в час: каталоги старше `RETENTION_DAYS` (7 по умолчанию) удаляются целиком (по `createdAt`, при нечитаемом `meta.json` по времени изменения каталога).
- На Railway `DATA_DIR=/data` — это подключённый Volume, данные переживают перезапуски.

## 4. Геометрия: как блок превращается в место в PDF

Файл: [server/src/core/placement.ts](server/src/core/placement.ts). Это самая важная часть для переноса на другой язык.

**Входные данные.** Блок в долях видимой страницы; геометрия страницы: `(boxX, boxY, boxWidth, boxHeight)` — прямоугольник страницы в пространстве PDF (CropBox, иначе MediaBox; начало координат PDF — левый нижний угол, ось y вверх) и `rotation` — `/Rotate` (по часовой стрелке при показе).

**Шаги.**
1. Видимый размер: при 0/180 это `(boxWidth, boxHeight)`, при 90/270 — `(boxHeight, boxWidth)`.
2. Блок в видимых пунктах: `bx = x·W, by = y·H, bw = width·W, bh = height·H` (`W, H` — видимые размеры).
3. Доступная область: `pad = 0.04 · min(bw, bh)`, `availW = bw − 2·pad`, `availH = bh − 2·pad`.
4. Масштаб: `s = min(availW / imgW, availH / imgH)`; размер картинки `w = imgW·s`, `h = imgH·s`.
5. Левый нижний угол картинки на видимой странице: `dx = bx + (bw − w)/2`, `dyBottom = by + (bh + h)/2` (ось y вниз).
6. Перевод точки видимой страницы `(dx, dy)` в пространство PDF:

   | rotation | x в PDF | y в PDF |
   |---|---|---|
   | 0 | `boxX + dx` | `boxY + boxHeight − dy` |
   | 90 | `boxX + dy` | `boxY + dx` |
   | 180 | `boxX + boxWidth − dx` | `boxY + dy` |
   | 270 | `boxX + boxWidth − dy` | `boxY + boxHeight − dx` |

7. Рисование: картинка с левым нижним углом в полученной точке, шириной `w`, высотой `h`, **поворот против часовой стрелки на `rotation` градусов** (параметр `rotate` у `drawImage` в `pdf-lib`).

Числовые контрольные значения (блок `x=0.1, y=0.7, width=0.4, height=0.12`, картинка 600×240, отступ 4%):

## 5. Драйверы планшета

Интерфейс (в [shared/src/index.ts](shared/src/index.ts)):

```ts
interface PadDriver {
  readonly kind: 'mock' | 'signotec';
  connect(): Promise<void>;
  capture(options: { prompt: string; signal?: AbortSignal }): Promise<SignatureCapture>;
  cancel(): Promise<void>;
  disconnect(): Promise<void>;
}
```

Ошибки только типа `PadError` с кодами: `service_unavailable` (служба не отвечает), `pad_not_found` (планшет не найден или занят), `cancelled`, `timeout`, `unknown`.

- **mock** — окно с холстом 640×320 (пропорция экрана планшета 2:1): рисование мышью и пальцем, кнопки «Подтвердить», «Очистить», «Отмена».
- **signotec** — см. раздел 3.4. Библиотека signotec `STPadServerLib.js` (3.5.0, лицензия MIT) лежит в [web/public/vendor/](web/public/vendor/) и подключается скриптом при первой подписи. В браузере она создаёт объект `window.STPadServerLib`.

Выбор драйвера: параметр адреса `?pad=mock|signotec`, затем сборочная переменная `VITE_PAD_DRIVER`, по умолчанию `mock`. На Railway сейчас задан `signotec`.

## 6. API

Префикс `/api`. Ошибки: HTTP-статус и тело `{"error": {"code", "message"}}`.

| Метод и адрес | Назначение | Успех |
|---|---|---|
| `POST /login` `{password}` | вход | 204 + cookie |
| `POST /logout` | выход | 204 |
| `GET /session` | `{authenticated}` (без входа доступен) | 200 |
| `POST /documents` (multipart `file`) | загрузка PDF | 201 `DocumentInfo` |
| `GET /documents/:id` | сведения о документе | 200 |
| `GET /documents/:id/file` | оригинал PDF | 200 PDF |
| `POST /documents/:id/sign` `SignRequest` | вставка подписи | 200 `SignResponse` |
| `GET /documents/:id/signed` | подписанный PDF | 200 PDF |
| `GET /health` (вне `/api`) | проверка живости | 200 `{"ok":true}` |

Коды ошибок: `unauthorized`, `bad_request`, `not_pdf`, `pdf_encrypted`, `pdf_invalid`, `file_too_large`, `document_not_found`, `invalid_blocks`, `invalid_signature`, `internal`. Подписать можно только с `padKind` `mock` или `signotec`.

## 7. Безопасность и приватность

- Документы клиентов — персональные данные. Доступ только по общему паролю; идентификаторы документов — случайные UUID; файлы на Volume с правами 0700; автоудаление через 7 дней.
- Реальные документы и секреты в репозиторий не попадают. В `samples/` только вымышленные файлы. `.env` игнорируется git.
- Пароль и ключ сессии задаются переменными окружения платформы. Пароль для вашего экземпляра лежит вне репозитория в `~/.config/e-sign/app-password`.
- Служба signotec на компьютере слушает локальный порт. В документации не описано, какие сайты вправе к ней обращаться; вопрос открыт.
- Известные ограничения: один общий пароль, без журнала аудита, без разграничения пользователей.

Dockerfile, railway.json   выкладка

## 10. Запуск и разработка

Нужен Node.js 22.

```bash
npm install
npm run typecheck && npm run lint && npm test && npm run build
npm run dev -w server      # сервер на :3000 (пароль dev)
npm run dev -w web         # сайт на :5173, /api проксируется на :3000
npm run samples            # пересоздать тестовые PDF в samples/
```

Проверенный путь на Mac без планшета: запустить сервер и сайт, открыть `http://localhost:5173/?pad=mock`, загрузить файл из `samples/`, отметить блоки, подписать в окне mock, скачать результат.

Тесты: 50 серверных (геометрия, вставка подписи, вход, документы, очистка), 88 веб (разметка блоков, экраны, драйверы с подменой библиотеки signotec) и 4 теста модуля для CRM.

## 11. Выкладка

Только через git: push в `main` → Railway собирает `Dockerfile` и выкладывает. Сервис `app` в проекте `e-sign`, Volume `/data`, переменные `APP_PASSWORD`, `SESSION_SECRET`, `DATA_DIR`, `RETENTION_DAYS`, `MAX_UPLOAD_MB`, `NODE_ENV`, `VITE_PAD_DRIVER`. Подробности и порядок настройки: [docs/DEPLOY.md](docs/DEPLOY.md). Контейнер стартует от root только ради прав на Volume и сразу переходит на пользователя `node`.

## 13. Что проверено и что нет

**Проверено:** вход, загрузка, разметка, подпись через mock, вставка в блоки (включая повёрнутую страницу и страницы со смещением CropBox), скачивание; всё это и на Railway. Планшет Sig100 и служба signotec работают на Windows (пример `STPadServer.html` дал подпись). Библиотека signotec загружается и содержит все методы, которые вызывает драйвер.

**Не проверено до конца:** полный проход «планшет → наш сайт → PDF» на Windows после последних правок; порядок кнопок на экране планшета и читаемость текста на экране 320×160; толщина линии подписи на реальном изображении; просмотр PDF в окне результата в обычном Chrome (во встроенном браузере Claude окно было пустым); Mac для планшета (в открытых материалах signotec поддержка macOS не найдена).

**Не сделано намеренно (пилот):** юридически значимая подпись (хэш, сертификат, защита от изменений после подписания), автоопределение мест подписи, несколько подписантов в одном документе, интеграция с документооборотом, учётные записи пользователей, журнал действий.
